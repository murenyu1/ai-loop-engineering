# Codex 侧栏定位与工作区排序

日期：2026-10-25。基线：dev/codex，ff808dd。用户确认方案并授权在 Codex 分支开发和中文 Git 提交。

## 实施方案与改动

1. Codex 双页面板在空参数入口中发起一次当前聊天定位消息。模型使用本聊天可信 SessionStart 上下文，或本聊天环境明确的工作区根目录，回调 `ai_loop.dashboard`。随机请求标识只关联本面板本次入口；后台发现读取回传结果，同时选中功能配置页和子 agent 看板的工作区。
2. MCP 服务在内存中登记有限、限时的定位请求，拒绝未登记请求、冲突聊天和已删除工作区。每次读取重新校验宿主工作区列表。手动选择使在途定位失效；迟到输入和结果不能覆盖选择。
3. 工作区发现统一按 AI Loop 已启用优先，再按真实本地聊天最近活动时间降序。只读当前最高版本 `state_N.sqlite`，兼容时间字段差异；明确的聊天项目归属优先于 cwd，未归属聊天只匹配最长且唯一的本地工作区根目录。归档聊天与无用户事件的子代理不参与排序；时间缺失保留宿主组内顺序，不使用项目修改时间猜测。
4. SQLite 为可选的 Node 内置能力；旧 Node、不兼容、缺失或不可用数据库仍能读取工作区与启用排序，最近使用排序退回稳定顺序。新增模块纳入 Codex 构建清单及源码映射，三版本构建同步受管发行产物。

## 验收边界

消息桥会在当前聊天发送定位请求，可能触发模型响应。宿主拒绝消息、无法确定可信根目录或两分钟未收到定位结果时显示原因并保留手选。只有真实 session 存在时展示当前聊天历史；仅有 root 时只定位工作区。不得使用插件进程 cwd、selected-project 或最近工作区冒充当前聊天。

本轮不修改 settings.json，不修改已安装插件、钩子信任或权限，不发布或推送。真实 Codex 侧栏消息投递、模型回调及安装后双页显示需客户端验收，自动测试不替代该项。
