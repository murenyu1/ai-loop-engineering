## 已复现的故障

DSH 看板把磁盘观察中的任意非路径字符串当作子会话 ID。截图对应运行的开发记录使用演示 ID，原生目录中只有另一条真实规划子会话。原代码会自行拼接 `continuable` 地址；新增 `uiWorkspace.openSession` 入口后，按钮能触发跳转，但目标没有真实历史。实机已复现跳转到空起始页；同一父聊天通过 DSH 原生目录打开真实规划子代理时，可以显示完整历史。

本机 DSH 已移除 `sessions.openSubagent` 和 `refreshSubagents`，提供 `uiWorkspace.openSession`、`sessions.refreshProjections`、`subagentAddress` 和 `retain`。`openSession` 返回空值，表示请求已发出，不能证明历史已加载。`retain` 返回的 `ready` 才能报告原生历史加载结果。

Codex 原实现仅凭 UUID 格式启用深链接，缺少线程存在性及真实父子关系校验。真实线程索引的 `source.subagent.thread_spawn.parent_thread_id` 和历史首行 `session_meta` 可提供交叉核验；其中 `payload.id` 是子线程 ID，而本机 `payload.session_id` 可能是父会话 ID，不能混用。长首行、Windows 长路径、已删除历史及跨工作区目标都需要单独处理。

Core 没有宿主看板页面，负责共享图数据、运行和观察。原有报告还确认了两个共享缺陷：知识 CLI 的部分命令忽略 `--project-path`；结构化 `issues` 直接拼接成为 `[object Object]`。本轮将分别修复并补回归，不改写历史记录来伪装有效上下文。

## 修复行为

- DSH 先刷新原生投影，取得与当前父聊天相符的真实地址，保留宿主实际模式；历史预加载成功后才导航。未知、演示、失效或错父地址不再拼接成 `continuable`。详情、全部调用等入口共用取消和代次控制，切换、返回旧聊天或卸载后不再接收旧请求，引用最终释放。
- Codex 使用只读线程索引和受限历史首行校验身份。默认历史、多目录工作区及单次运行均返回导航证明；点击时重新核验。显式 `session_id` 可以与工具路径形式的 `context.id` 分开，只有经过原生验证的 UUID 能进入深链接。
- 知识库的存储基址与来源基址分开：`--project-path` 决定子库，文件和事件来源仍相对原工作区。搜索返回可直接传给读取 API 的项目范围参数；历史备份、正文及分页指针能从原工作区定位；未初始化子库不回退根库，拼错项目路径不会自动创建项目。
- 结构化问题摘要保留未知字段，包括 `description/file/location`，权限停止门禁保持有效。记录角色游标、Codex 模型字段和分级 schema 说明按当前实现校准。
