## 日常接手

1. 读 `AGENTS.md` 与当前交接，执行 `git status --short`、`git log -6 --oneline`，核对实际文件。已有修改先确认归属，不 reset、clean、覆盖或擅自 stash。
2. 同一目录的两个客户端共享工作区；切分支会同时影响另一端。不要同时在此目录维护不同分支。并发开发应使用独立克隆或 Git worktree，先按项目规则获得适用授权，并明确不重叠的文件归属。
3. 新开发分支使用 `codex/<主题>` 或 `dsh/<主题>`。若本地有未提交改动，保留现场；先协调，再切换分支。不要给另一端覆盖工作区。
4. 不同克隆先在网络可用时执行 `git fetch origin`，查看 `git log --left-right --oneline HEAD...origin/main`。已有正常追踪分支按项目合并策略同步；遇分叉先评审，不强推。
5. 每个可审查阶段提交代码和交接记录。交接写清基准提交、实现文件/符号、验证命令与结果、未验收项、下一步及负责人。提交后以 `git log` 核对真实提交，不在被提交文件中硬填其自身提交哈希。
6. 运行 `node tests/all.mjs`。构建使用 `node scripts/build-release.mjs`，并检查两种插件产物。真实宿主界面、加载和模型执行分别记录，不能以单元测试替代。

源码和已安装插件是不同副本。使用新阶段或批次契约前，统一升级参与同一运行的两端核心；不要让旧插件写新版运行。不手改状态兼容旧客户端。

## 交接格式

每个主题使用一个记录，至少包含：目标、基准提交、批准范围、已完成内容、验证证据、明确未完成项、下一步、文件归属。恢复时优先读记录引用的符号，再读取必要的本机 `.ai-loop/` 资料。共享记录只提供交接事实，不替代核心 `state.json`，也不自动授权继续开发。
