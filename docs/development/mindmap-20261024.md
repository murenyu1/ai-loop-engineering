# 纵向工作流图与统一调度交接

状态：fix2 图节点命名空间补修已完成；全量验证与独立复评待主代理统一执行。日期：2026-10-24。

## 目标与已确认决策

Codex 与 DSH 看板复用同一自包含 `createWorkflowGraph` 函数，纵向显示主代理、总体计划、正式任务、阶段交接和统一记录。节点配色、尺寸、图例和交互语义共用；真实原生调用边只由活动观察中的匹配父子上下文产生。

主代理统一拆分、派发和验收。复杂任务可按需让一个 run 级 planner 提建议；主代理批准后再创建正式 task。scribe 默认一个 run 共用，在阶段结束、阻塞或交付时批量整理，不为每条分支单独派发。

## 当前实现

- `core/scripts/workflow-graph.mjs` 接受 `{ run, activity }`；读取 `run.workflow` 或可选 spec workflow，并输出带坐标的节点、边、尺寸、警告、主题颜色与图例。旧运行按正式任务、依赖和活动观察生成默认图。
- 可选 `spec.workflow` 结构为 `nodes: [{ id, task, role, label? }]` 与 `edges: [{ from, to }]`。创建时校验唯一节点 ID、task+role 绑定、合法引用及 DAG。`run` 只允许 planner/scribe，`final` 只允许整体 tester/reviewer。指定显式图后，任何未列出的角色调用会被核心拒绝。
- DAG 分支、汇合和依赖通过任务卡与阶段卡纵向布局。任务头只连接该任务在原始 DAG 中的入口阶段，跨任务交接仍直接连接真实阶段，避免布局转换制造循环。循环或缺失的旧依赖产生警告；没有跨任务交错边的任务可折叠为汇总卡。与其他任务交错连接的任务折叠时保留阶段并显示原因，避免折叠转换丢失合法节点。
- 显式 DAG 每一行按最大行宽居中；总体根节点和单节点汇合行保持画布中线对齐。
- Codex 与 DSH 各自构建时注入同一图函数；`UI_THEME` 提供共同卡片尺寸和角色色。通用阶段职责、Codex/DSH 路由和两端 ai-loop 技能已补充统一调度约定。
- 没有显式 workflow 的旧运行保持可读；虚拟运行与整体阶段使用 `system:` 节点 ID，正式任务阶段仍为 `stage:<task>:<role>`。旧正式 task id 为 `run` 或 `final` 时，活动观察只归属对应正式任务，不重复挂到虚拟总体计划/整体验证/整体评审；正式 task 的额外 `scribe` 观察保留在任务卡详情。新 workflow spec 保留 `run` 与 `final`，拒绝造成归属歧义。

## 能力边界与验证

核心仍按同一正式 task+role 执行锁定。同一任务多个同角色执行者不能并行；多个独立方向需拆成不同正式 task 并声明互斥范围。流程图边只表示批准的交接拓扑，不替代 `depends_on`、任务阶段、快照验证或评审证据。开发写入收敛后，验证和评审仍按当前快照门禁进行。原生代理 `completed` 只表示调用结束，不能当作 PASS。
