## 行为与实现

- 共享策略：`core/scripts/roles.mjs` 提供默认关闭、显式开启与乐观并发保存；`activity.mjs` 负责任务阶段、批次、原生 ID、重复执行和最后观察。关闭不探测角色模型，实际 usage 缺失为 null。磁盘观察不承诺实时。
- 新角色策略快照可写入运行 spec.role_policy，使用 schema 3 阻止旧核心写入；不带该字段的旧运行和安全 schema 1/2 仍按原证据门禁工作。schema 3 保留 finish、attempt、范围、修复次数和独立评审约束。
- 原生模型配置 schema 2 增加 enabled；旧 schema 1 校验和摘要不变，已有显式模型继续保留。`balanced` 仍是用户显式选择的启用预设。关闭时保留先前模型，不能把 off 作为模型名发送给宿主。
- Codex 原生设置合并保存工作区自动入口和模型草稿。只关闭角色或只修改工作区不依赖模型目录可用性；保存失败保留草稿并回滚工作区变更。旧独立开关动作保留协议兼容时不再作为正式设置按钮展示。
- Codex 看板以包内 MCP UI 资源和 thread 入口提供，通过本地 stdio 工具读登记工作区、运行与代理观察，不开 localhost 服务、不拉取外部 UI、不调用模型。缺少可靠的会话到工作区映射时明确选择工作区，不伪称自动绑定。
- DSH 继续使用原生 spawn 生命周期，结构化参数关联 run/task/attempt；角色关闭先阻止调用，执行中关闭须等原生退出确认。客户端用会话工作区或明确选择隔离数据，不能自动回退到其他工作区。公开取消能力不可确认时显示待停止，不能用 core.stop 冒充进程已结束。

## 使用与后续

通用包：先 `roles.mjs status --project ROOT`，需要的角色用 `set --role dev --enabled true --model ID --apply` 开启；`--enabled false --apply` 关闭。各插件使用本平台原生设置，不混用另一平台的模型文件。运行前确认参与同一运行的核心都支持所用 schema；升级源码不会自动升级已安装插件。
