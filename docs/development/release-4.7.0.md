## 最终实现与契约

单项目新运行保存到 `<project>/.ai-loop/runs/`；跨项目运行保存到工作区根。旧集中运行不自动迁移。所有路径仍以创建运行时的工作区根解释；换聊天或 Harness 时保持该根并使用 `--project-path`，不能把子目录当成原工作区后沿用旧快照范围。

同名运行必须明确 `project_path`。核心 API 使用可选末尾 `{ project_path }`；storage 路径入口使用项目路径字符串。状态、修改锁、执行证据与交接使用相同基址。未指定项目且存在同编号候选时明确报错，不自动猜选。聊天历史保持父聊天隔离，损坏 JSON 单独计数；权限与其他验证错误继续显式抛出。

不同项目的本地运行可使用相同编号；集中目录已经占用该编号时，新创建请求明确拒绝并要求另选编号，不能覆盖旧记录。创建锁使用工作区身份，运行中的修改锁继续使用实际记录基址。

DSH `ai_loop_plan` 只启动已开启的原生 planner，不创建正式 run/task，不自动进入开发。计划只允许写本项目 `.ai-loop/plans/<plan_id>/`。`ai_loop_observe({plan_id, project_path})` 返回真实运行/完成/失败/取消观察和可序列化原生结果；主代理经获准原生文件工具保存证据。`persistence: pending-native-write` 表示尚待落盘，不能当成已经保存或计划已经获批。插件重载后的内存观察缺失须向原生运行时核对，不猜测或重派。

Codex 页面内部只调用无 UI 的数据工具；不发送定位消息，不要求模型回调打开面板。全局保存、周期状态读取、关闭保护与同名运行选择均有回归。只有宿主返回可导航会话 ID 时才提供子代理聊天入口，角色别名不能伪装成会话 ID。

## 实际宿主与后续边界

本轮未自动操作 Codex 桌面 UI，未升级已安装插件，也未完成新版真实 DSH/Codex 点击、保存、原生 planner 文件落盘和新聊天钩子端到端验收。自动测试不替代这些实机检查。此前用户确认的子代理上下文导航与状态自动显示属于 4.6.4 的历史证据。

静态 Codex 侧栏缺少可信 root/session 时仍需手选，不能依据最近工作区或其他聊天推断归属。实际模型/强度与 token 用量不可观测时保持 unverified；已运行代理和旧页面不会随源码发布热更新。跨机器重新克隆只能恢复已同步的交接资料；被 Git 忽略且未另行同步的本机 `.ai-loop/` 不会自动出现。

后续提升方向：在具备真实宿主验收环境时补充点击与原生文件落盘检查；为新增存储布局建立跨根目录迁移命令和显式升级识别；持续约束大型工作区的发现与历史扫描开销。上述能力不冒称本轮已交付。
