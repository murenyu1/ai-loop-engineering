# AI Loop 模型设置

插件根目录是本文件上两级目录。先确认本次工作区和目标项目，再使用插件的原生设置或脚本；不要把源包或插件目录当作目标项目。

用户希望直接操作时，优先指引到 Codex 的 AI Loop Engineering 插件详情页原生设置区。该区用“全局默认／仅当前工作区”选择范围，选择工作区时默认项目范围；支持、从自动读取的 Codex 本机工作区列表中直接选择项目、工作区自动入口与模型草稿统一应用、配置 planner/reviewer/dev/tester/scribe 的模型和思考深度、调整并发，并提供应用草稿和恢复项目继承的动作。选择工作区不写配置，新项目默认停用；无需手填路径或单独登记。只把当前原生模型列表列出的模型与该模型支持的强度作为候选；服务端保存前还会复核。

设置页是否出现受当前 Codex 客户端能力和功能开关影响。页面可见性与保存效果须在所用客户端验收。不要声称静态协议检查或自动测试证明 UI 已显示；不要改私有功能开关、`settings.json` 或信任缓存，也不要用外部浏览器面板替代原生设置。

1. 保存时明确告知作用范围。全局配置影响所有后续使用该插件的项目；项目配置只覆盖当前选中项目。恢复项目继承会撤销本工具拥有的项目覆盖，并重新采用全局设置。
2. 五个子代理角色可以分别使用不同模型和支持的思考强度。主会话模型继续由 Codex 原生选择器控制，不通过此插件设置切换。
3. 配置仅对原生重载后的后续派发生效；运行中的代理不会热切换。需要改变当前执行配置时，先安全停止并保存交接，再重载并核对原生角色发现与实际调用。
4. 页面暂不可用时，可在用户要求下使用插件 `scripts/plugin-models.mjs` 的 `status|list|configure|set|reset` 命令；写入先预演，再对照用户选择应用。命令的实际选项以脚本 `--help` 为准。没有可信模型列表时询问用户，不用预设替代可用性核验。
5. 原生角色文件由正常用户宿主进程管理，保留备份和人工修改保护。遇到 deny 或所有者异常，停止配置写入，不提权绕过，也不批量调整 ACL。

脚本帮助：`node PLUGIN/scripts/plugin-models.mjs --help`。配置成功、原生发现、模型推理生效分别报告；未知状态保持未验证。

4.5.0 角色策略：未配置默认全部关闭，设置模型菜单的“关闭”映射 enabled=false，不把它当模型 ID。保存保留原模型，关闭或仅改自动入口不依赖模型目录。doctor dispatch=disabled 时由主代理继续工作，不能调用已发现但已关闭的角色；保留的原生文件不是启用证据。运行中停止需原生确认，independent 要求不能自动降级。包内 MCP thread 看板不启动 HTTP；真实客户端渲染、实际模型及 UI 仍分别验收。
