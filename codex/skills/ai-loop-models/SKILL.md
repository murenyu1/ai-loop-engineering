# Codex 原生模型与插件设置规范

本技能用于指导在 Codex 原生插件设置页配置 AI Loop 工作区及各角色模型。
所有配置由宿主原生机制安全保存，严禁使用外部脚本或修改 `settings.json` 绕过宿主设置。

## 配置范围与工作区管理

1. **作用范围**：
   - 全局默认（Global Default）：影响所有后续使用该插件的工作区；
   - 仅当前工作区（Project Override）：针对当前项目的精确配置，覆盖全局设置；
   - 恢复项目继承（Reset Inheritance）：撤销当前项目的独立配置，重新继承全局设置。
2. **工作区安全机制**：
   - 自动读取 Codex 本机工作区列表，直接在列表中选择启用；
   - 新检测到的工作区默认停用，避免未授权项目自动加载工作流；
   - 选择工作区不直接写配置，点击统一应用（Apply）后才正式落盘。

## 角色模型路由与并发

1. **五角色模型配置**：
   - 角色包含 `planner`、`dev`、`tester`、`reviewer`、`scribe`；
   - 首次未配置时默认全部角色关闭；
   - 开启角色时，`provider` 与 `model` 必须成对选择；思考深度（`reasoningEffort`）仅使用目标模型实际支持的等级；
   - 主会话模型继续由 Codex 原生模型选择器控制，不受子代理配置影响。
2. **并发与生效边界**：
   - 并发设置限制同一项目内允许同时处于活跃状态的子代理数量；
   - 配置仅对后续派发或插件重载后的执行生效，运行中的子代理不发生热切换；
   - 严禁在 Windows 沙箱权限异常时批量修改 ACL 或提权绕过安全策略。
